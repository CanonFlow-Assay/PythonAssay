# Playground convergence — phase 1

ExpenseGuard already isolates the native immutable decision core from its CLI and
evidence shell, retains baseline/mutation observations and makes offline advice
non-authoritative. PythonAssay itself remains a lexical checker with bounded
scope, not a semantic functional verifier.

The next safe application increment is a key/value configuration firewall: a
shell maps supplied values to validated immutable settings or explicit issues,
then tests its positive, negative and freshness cases with the existing runner.
Do not turn checker configuration into a general rules language, claim that a
clean lexical receipt proves the sample, or add time/serialization machinery
without a declared application need.
